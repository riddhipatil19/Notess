## What is a One-to-Many Relationship?

A one-to-many relationship exists when one record in the first table can be associated with multiple records in the second table, but each record in the second table relates to only one record in the first table.

**Examples:**

- One customer can have many orders
- One department can have many employees
- One author can write many books

## Basic Table Structure

```sql
-- Parent Table (One side)
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(100),
    email VARCHAR(100)
);

-- Child Table (Many side)
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    total_amount DECIMAL(10,2),
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
        ON DELETE CASCADE  -- Automatically delete orders when customer is deleted
        ON UPDATE CASCADE  -- Update order's customer_id when customer's ID changes
);
```

## Types of Joins for One-to-Many

### 1. INNER JOIN

Returns only records that have matching values in both tables.

```sql
SELECT c.customer_name, o.order_id, o.order_date, o.total_amount
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id;
```

**Result:** Only customers who have placed orders

### 2. LEFT JOIN (LEFT OUTER JOIN)

Returns all records from the left table and matched records from the right table.

```sql
SELECT c.customer_name, o.order_id, o.order_date, o.total_amount
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id;
```

**Result:** All customers, including those without orders (NULL values for order fields)

### 3. RIGHT JOIN (RIGHT OUTER JOIN)

Returns all records from the right table and matched records from the left table.

```sql
SELECT c.customer_name, o.order_id, o.order_date, o.total_amount
FROM customers c
RIGHT JOIN orders o ON c.customer_id = o.customer_id;
```

**Result:** All orders, including orphaned orders (unlikely in well-designed databases)

### 4. FULL OUTER JOIN

Returns all records when there's a match in either table.

```sql
SELECT c.customer_name, o.order_id, o.order_date, o.total_amount
FROM customers c
FULL OUTER JOIN orders o ON c.customer_id = o.customer_id;
```

**Result:** All customers and all orders, with NULLs where no match exists

### 5. CROSS JOIN

Returns the Cartesian product of both tables (every row from first table combined with every row from second table).

```sql
-- Basic CROSS JOIN
SELECT c.customer_name, o.order_id, o.order_date, o.total_amount
FROM customers c
CROSS JOIN orders o;

-- Alternative syntax (without CROSS JOIN keyword)
SELECT c.customer_name, o.order_id, o.order_date, o.total_amount
FROM customers c, orders o;
```

**Result:** Every customer paired with every order (usually not useful for one-to-many relationships) **Warning:** Can create extremely large result sets. If customers table has 100 rows and orders has 1000 rows, result will have 100,000 rows!

## Common Use Cases and Examples

### Finding Customers with Orders

```sql
-- Customers who have placed orders
SELECT DISTINCT c.customer_name
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id;
```

### Finding Customers without Orders

```sql
-- Customers who haven't placed any orders
SELECT c.customer_name
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.customer_id IS NULL;
```

### Counting Related Records

```sql
-- Count orders per customer
SELECT c.customer_name, COUNT(o.order_id) as order_count
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
```

### Finding Top Customers

```sql
-- Customers with total order amounts
SELECT c.customer_name, 
       COUNT(o.order_id) as total_orders,
       SUM(o.total_amount) as total_spent
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
ORDER BY total_spent DESC;
```

## INNER JOIN with GROUP BY

### Basic Aggregations

```sql
-- Count orders per customer (only customers with orders)
SELECT c.customer_name, COUNT(o.order_id) as total_orders
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
ORDER BY total_orders DESC;

-- Average order amount per customer
SELECT c.customer_name, 
       COUNT(o.order_id) as order_count,
       AVG(o.total_amount) as avg_order_amount,
       SUM(o.total_amount) as total_spent
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
```

### Date-based Aggregations

```sql
-- Orders per customer by year
SELECT c.customer_name, 
       YEAR(o.order_date) as order_year,
       COUNT(o.order_id) as orders_per_year,
       SUM(o.total_amount) as yearly_total
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name, YEAR(o.order_date)
ORDER BY c.customer_name, order_year;

-- Monthly sales summary
SELECT YEAR(o.order_date) as year,
       MONTH(o.order_date) as month,
       COUNT(DISTINCT c.customer_id) as unique_customers,
       COUNT(o.order_id) as total_orders,
       SUM(o.total_amount) as monthly_revenue
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY YEAR(o.order_date), MONTH(o.order_date)
ORDER BY year, month;
```

### Using HAVING with INNER JOIN

```sql
-- Customers with more than 5 orders
SELECT c.customer_name, COUNT(o.order_id) as total_orders
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
HAVING COUNT(o.order_id) > 5
ORDER BY total_orders DESC;

-- High-value customers (spent more than $1000)
SELECT c.customer_name, 
       COUNT(o.order_id) as order_count,
       SUM(o.total_amount) as total_spent
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
HAVING SUM(o.total_amount) > 1000
ORDER BY total_spent DESC;
```

## LEFT JOIN with GROUP BY

### Including All Parent Records

```sql
-- Count orders for ALL customers (including those with 0 orders)
SELECT c.customer_name, COUNT(o.order_id) as order_count
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
ORDER BY order_count DESC;

-- Customer summary with safe aggregations
SELECT c.customer_name,
       COUNT(o.order_id) as order_count,
       COALESCE(SUM(o.total_amount), 0) as total_spent,
       COALESCE(AVG(o.total_amount), 0) as avg_order_amount
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
```

### Identifying Inactive Customers

```sql
-- Customers who haven't ordered in the last 6 months
SELECT c.customer_name,
       MAX(o.order_date) as last_order_date,
       COUNT(o.order_id) as total_orders
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
HAVING MAX(o.order_date) < DATE_SUB(CURDATE(), INTERVAL 6 MONTH) 
       OR MAX(o.order_date) IS NULL
ORDER BY last_order_date;

-- Customers with no orders at all
SELECT c.customer_name, c.email
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name, c.email
HAVING COUNT(o.order_id) = 0;
```

### Comparing INNER vs LEFT JOIN Results

```sql
-- Side-by-side comparison showing the difference
-- Active customers only (INNER JOIN behavior)
SELECT 'Active Customers' as category, COUNT(*) as customer_count
FROM (
    SELECT c.customer_id
    FROM customers c
    INNER JOIN orders o ON c.customer_id = o.customer_id
    GROUP BY c.customer_id
) active_customers

UNION ALL

-- All customers (LEFT JOIN behavior)
SELECT 'All Customers' as category, COUNT(*) as customer_count
FROM (
    SELECT c.customer_id
    FROM customers c
    LEFT JOIN orders o ON c.customer_id = o.customer_id
    GROUP BY c.customer_id
) all_customers;
```

### Complex Aggregations with Multiple Conditions

```sql
-- Customer segmentation analysis
SELECT c.customer_name,
       COUNT(o.order_id) as total_orders,
       SUM(o.total_amount) as total_spent,
       COUNT(CASE WHEN o.order_date >= DATE_SUB(CURDATE(), INTERVAL 3 MONTH) 
                  THEN 1 END) as recent_orders,
       CASE 
           WHEN COUNT(o.order_id) = 0 THEN 'No Orders'
           WHEN COUNT(o.order_id) >= 10 AND SUM(o.total_amount) >= 1000 THEN 'VIP'
           WHEN COUNT(o.order_id) >= 5 THEN 'Regular'
           ELSE 'Occasional'
       END as customer_segment
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
ORDER BY total_spent DESC;
```

## Key Differences: INNER vs LEFT JOIN with GROUP BY

### INNER JOIN with GROUP BY

- **Only includes parent records that have related child records**
- **COUNT() will never be 0** (always at least 1 match)
- **SUM() and AVG() work normally** (no NULL concerns)
- **Useful for:** Active customer analysis, performance metrics

### LEFT JOIN with GROUP BY

- **Includes ALL parent records** regardless of child records
- **COUNT() can be 0** for parents with no children
- **SUM() and AVG() can return NULL** (use COALESCE for safety)
- **Useful for:** Complete customer lists, identifying inactive records

### Practical Example Comparison

```sql
-- INNER JOIN: Only customers with orders
SELECT c.customer_name, COUNT(o.order_id) as orders
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
-- Result: 250 customers (only those who ordered)

-- LEFT JOIN: All customers
SELECT c.customer_name, COUNT(o.order_id) as orders
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
-- Result: 300 customers (including 50 who never ordered)
```

## Referential Integrity and CASCADE Options

### ON DELETE CASCADE

When you delete a parent record, automatically delete all related child records.

```sql
-- Table with CASCADE delete
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    total_amount DECIMAL(10,2),
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
        ON DELETE CASCADE
);

-- Example: This will delete customer AND all their orders
DELETE FROM customers WHERE customer_id = 123;
```

### Other CASCADE Options

```sql
-- ON DELETE RESTRICT: Prevent deletion if child records exist
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
    ON DELETE RESTRICT;

-- ON DELETE SET NULL: Set foreign key to NULL when parent is deleted
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
    ON DELETE SET NULL;

-- ON DELETE SET DEFAULT: Set foreign key to default value
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
    ON DELETE SET DEFAULT;

-- ON UPDATE CASCADE: Update foreign key when parent key changes
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
    ON UPDATE CASCADE;
```

### Testing CASCADE Behavior

```sql
-- Insert test data
INSERT INTO customers (customer_id, customer_name, email) 
VALUES (100, 'Test Customer', 'test@email.com');

INSERT INTO orders (order_id, customer_id, order_date, total_amount)
VALUES (1001, 100, '2024-01-15', 250.00);

-- This will delete both customer and their orders (with CASCADE)
DELETE FROM customers WHERE customer_id = 100;

-- Verify orders are gone too
SELECT * FROM orders WHERE customer_id = 100; -- Returns no rows
```

## CROSS JOIN Use Cases

### When to Use CROSS JOIN

1. **Creating all possible combinations** for analysis
2. **Generating test data**
3. **Creating matrix reports**
4. **Calculating differences between all pairs**

### Practical CROSS JOIN Examples

```sql
-- Generate all product-store combinations for inventory setup
SELECT s.store_name, p.product_name, 0 as initial_stock
FROM stores s
CROSS JOIN products p;

-- Create all possible customer-product combinations for recommendations
SELECT c.customer_id, p.product_id
FROM customers c
CROSS JOIN products p
WHERE p.category = 'Electronics';

-- Calculate price differences between all product pairs
SELECT p1.product_name as product1, 
       p2.product_name as product2,
       ABS(p1.price - p2.price) as price_difference
FROM products p1
CROSS JOIN products p2
WHERE p1.product_id < p2.product_id; -- Avoid duplicates
```

## Key Points to Remember

### Performance Considerations

- Use appropriate indexes on join columns
- Consider the size of result sets when using LEFT JOINs
- INNER JOINs are typically faster than OUTER JOINs

### Best Practices

1. **Always specify join conditions** to avoid Cartesian products (except when using CROSS JOIN intentionally)
2. **Use table aliases** for better readability
3. **Be careful with NULLs** in outer joins
4. **Consider using EXISTS/NOT EXISTS** for existence checks instead of joins when you don't need data from the related table
5. **Use CASCADE options carefully** - they can lead to unintended data loss
6. **Avoid CROSS JOIN** unless you specifically need all combinations

### Common Pitfalls

- **Cartesian Products:** Forgetting join conditions (or using CROSS JOIN unintentionally)
- **Duplicate Results:** Not understanding that one-to-many creates multiple rows
- **NULL Confusion:** Misunderstanding NULL behavior in outer joins
- **Wrong Join Type:** Using INNER JOIN when you need LEFT JOIN or vice versa
- **CASCADE Disasters:** Accidentally deleting important data with ON DELETE CASCADE
- **CROSS JOIN Performance:** Creating massive result sets unintentionally

## Advanced Examples

### Multiple One-to-Many Joins

```sql
-- Customers, their orders, and order items
SELECT c.customer_name, o.order_date, oi.product_name, oi.quantity
FROM customers c
INNER JOIN orders o ON c.customer_id = o.customer_id
INNER JOIN order_items oi ON o.order_id = oi.order_id
ORDER BY c.customer_name, o.order_date;
```

### Conditional Joins

```sql
-- Recent orders only
SELECT c.customer_name, o.order_date, o.total_amount
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id 
                   AND o.order_date >= '2024-01-01'
WHERE c.customer_name LIKE 'A%';
```

## Summary

One-to-many joins are fundamental in relational databases. Choose your join type based on what data you need:

- **INNER JOIN:** Only records with relationships
- **LEFT JOIN:** All parent records, with or without children
- **RIGHT JOIN:** All child records (rarely used in one-to-many)
- **FULL OUTER JOIN:** Everything (comprehensive view)
- **CROSS JOIN:** All possible combinations (use with caution)

**CASCADE Options Summary:**

- **ON DELETE CASCADE:** Automatically delete child records
- **ON DELETE RESTRICT:** Prevent parent deletion if children exist
- **ON DELETE SET NULL:** Set foreign key to NULL
- **ON UPDATE CASCADE:** Update foreign keys when parent key changes

Remember that one-to-many joins can multiply your result rows, so always consider grouping and aggregation when needed. Use CASCADE options judiciously to maintain data integrity while avoiding accidental data loss.
