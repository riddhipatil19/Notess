## 1. SELECT Clause

**Purpose:** Specifies which columns to retrieve from the database

**Syntax:**

```sql
SELECT column1, column2, ...
FROM table_name;
```

**Examples:**

```sql
-- Select specific columns
SELECT first_name, last_name FROM employees;

-- Select all columns
SELECT * FROM products;

-- Select with aliases
SELECT first_name AS fname, last_name AS lname FROM employees;

-- Select with calculations
SELECT price * quantity AS total_cost FROM order_items;
```

**Key Points:**

- Use `*` to select all columns
- Use `AS` for column aliases
- Can perform calculations and functions
- Use `DISTINCT` to eliminate duplicates

## 2. FROM Clause

**Purpose:** Specifies the table(s) to retrieve data from

**Syntax:**

```sql
FROM table_name
FROM table1, table2  -- Cartesian product
FROM table1 JOIN table2 ON condition
```

**Examples:**

```sql
-- Single table
FROM employees

-- Multiple tables (implicit join)
FROM employees, departments

-- Subquery as source
FROM (SELECT * FROM active_employees) AS ae
```

## 3. WHERE Clause

**Purpose:** Filters rows based on specified conditions

**Syntax:**

```sql
WHERE condition
```

**Examples:**

```sql
-- Basic conditions
WHERE age > 25
WHERE department = 'Sales'
WHERE salary BETWEEN 50000 AND 80000

-- Multiple conditions
WHERE age > 25 AND department = 'Sales'
WHERE salary > 60000 OR bonus IS NOT NULL

-- Pattern matching
WHERE name LIKE 'John%'
WHERE email LIKE '%@gmail.com'

-- IN operator
WHERE department IN ('Sales', 'Marketing', 'HR')

-- NULL checks
WHERE phone_number IS NULL
WHERE bonus IS NOT NULL
```

**Operators:**

- Comparison: `=`, `!=`, `<>`, `<`, `>`, `<=`, `>=`
- Logical: `AND`, `OR`, `NOT`
- Pattern: `LIKE`, `ILIKE`
- Range: `BETWEEN`, `IN`
- NULL: `IS NULL`, `IS NOT NULL`

## 4. GROUP BY Clause

**Purpose:** Groups rows that have the same values in specified columns

**Syntax:**

```sql
GROUP BY column1, column2, ...
```

**Examples:**

```sql
-- Group by single column
SELECT department, COUNT(*) 
FROM employees 
GROUP BY department;

-- Group by multiple columns
SELECT department, job_title, AVG(salary)
FROM employees 
GROUP BY department, job_title;

-- Group by expression
SELECT YEAR(hire_date) AS hire_year, COUNT(*)
FROM employees 
GROUP BY YEAR(hire_date);
```

**Key Points:**

- Used with aggregate functions (COUNT, SUM, AVG, MIN, MAX)
- All non-aggregate columns in SELECT must be in GROUP BY
- Creates one row per group

## 5. HAVING Clause

**Purpose:** Filters groups created by GROUP BY (like WHERE but for groups)

**Syntax:**

```sql
HAVING condition
```

**Examples:**

```sql
-- Filter groups by aggregate values
SELECT department, COUNT(*) as emp_count
FROM employees 
GROUP BY department
HAVING COUNT(*) > 5;

-- Multiple conditions
SELECT department, AVG(salary) as avg_sal
FROM employees 
GROUP BY department
HAVING AVG(salary) > 60000 AND COUNT(*) >= 3;

-- Using aliases
SELECT department, COUNT(*) as emp_count
FROM employees 
GROUP BY department
HAVING emp_count > 10;
```

**Key Points:**

- Must come after GROUP BY
- Can use aggregate functions in conditions
- Cannot reference columns not in GROUP BY (unless aggregated)

## 6. ORDER BY Clause

**Purpose:** Sorts the result set by specified columns

**Syntax:**

```sql
ORDER BY column1 [ASC|DESC], column2 [ASC|DESC], ...
```

**Examples:**

```sql
-- Single column sorting
SELECT * FROM employees ORDER BY last_name;

-- Multiple columns
SELECT * FROM employees 
ORDER BY department ASC, salary DESC;

-- By column position
SELECT first_name, last_name, salary 
FROM employees 
ORDER BY 3 DESC;  -- Sort by 3rd column (salary)

-- By expression
SELECT first_name, last_name, salary 
FROM employees 
ORDER BY salary * 1.1 DESC;

-- With NULL handling
SELECT * FROM employees 
ORDER BY commission NULLS LAST;
```

**Key Points:**

- `ASC` (ascending) is default
- `DESC` for descending order
- Can sort by column position numbers
- `NULLS FIRST` or `NULLS LAST` for NULL handling

## 7. LIMIT/TOP Clause

**Purpose:** Restricts the number of rows returned

**Syntax:**

```sql
-- MySQL, PostgreSQL
LIMIT number_of_rows
LIMIT offset, number_of_rows

-- SQL Server
TOP number_of_rows

-- Oracle
ROWNUM <= number
```

**Examples:**

```sql
-- Get first 10 rows
SELECT * FROM employees LIMIT 10;

-- Skip 5 rows, then get 10
SELECT * FROM employees LIMIT 5, 10;  -- MySQL
SELECT * FROM employees LIMIT 10 OFFSET 5;  -- PostgreSQL

-- SQL Server
SELECT TOP 10 * FROM employees;

-- With ORDER BY for consistent results
SELECT * FROM employees 
ORDER BY hire_date DESC 
LIMIT 5;
```

## 8. JOIN Clauses

**Purpose:** Combines rows from multiple tables based on relationships

### INNER JOIN

```sql
SELECT columns
FROM table1
INNER JOIN table2 ON table1.column = table2.column;
```

### LEFT JOIN (LEFT OUTER JOIN)

```sql
SELECT columns
FROM table1
LEFT JOIN table2 ON table1.column = table2.column;
```

### RIGHT JOIN (RIGHT OUTER JOIN)

```sql
SELECT columns
FROM table1
RIGHT JOIN table2 ON table1.column = table2.column;
```

### FULL OUTER JOIN

```sql
SELECT columns
FROM table1
FULL OUTER JOIN table2 ON table1.column = table2.column;
```

**Examples:**

```sql
-- Inner join
SELECT e.first_name, e.last_name, d.department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;

-- Left join (all employees, even without department)
SELECT e.first_name, e.last_name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id;

-- Multiple joins
SELECT e.first_name, d.department_name, p.project_name
FROM employees e
JOIN departments d ON e.department_id = d.id
JOIN projects p ON e.project_id = p.id;
```

## 9. UNION Clause

**Purpose:** Combines results from multiple SELECT statements

**Syntax:**

```sql
SELECT columns FROM table1
UNION [ALL]
SELECT columns FROM table2;
```

**Examples:**

```sql
-- Remove duplicates (default)
SELECT first_name, last_name FROM employees
UNION
SELECT first_name, last_name FROM contractors;

-- Keep duplicates
SELECT department FROM employees
UNION ALL
SELECT department FROM temp_workers;
```

**Key Points:**

- Same number of columns in each SELECT
- Compatible data types
- `UNION` removes duplicates, `UNION ALL` keeps them
- Column names from first SELECT are used

## 10. Subquery Clauses

**Purpose:** Nested queries within other SQL statements

**Examples:**

```sql
-- Subquery in WHERE
SELECT * FROM employees
WHERE department_id IN (
    SELECT id FROM departments 
    WHERE location = 'New York'
);

-- Subquery in FROM
SELECT avg_sal.department, avg_sal.average_salary
FROM (
    SELECT department, AVG(salary) as average_salary
    FROM employees
    GROUP BY department
) AS avg_sal
WHERE avg_sal.average_salary > 70000;

-- Correlated subquery
SELECT * FROM employees e1
WHERE salary > (
    SELECT AVG(salary) 
    FROM employees e2 
    WHERE e2.department = e1.department
);
```

## SQL Query Execution Order

The logical order of SQL clause execution:

1. **FROM** - Identify source tables
2. **WHERE** - Filter individual rows
3. **GROUP BY** - Group rows
4. **HAVING** - Filter groups
5. **SELECT** - Choose columns
6. **ORDER BY** - Sort results
7. **LIMIT/TOP** - Restrict number of rows

## Common Aggregate Functions

Used with GROUP BY and HAVING:

- `COUNT(*)` - Count all rows
- `COUNT(column)` - Count non-NULL values
- `SUM(column)` - Sum numeric values
- `AVG(column)` - Average of numeric values
- `MIN(column)` - Minimum value
- `MAX(column)` - Maximum value
- `STRING_AGG(column, delimiter)` - Concatenate strings (PostgreSQL)
- `GROUP_CONCAT(column)` - Concatenate strings (MySQL)

## Best Practices

1. **Always use table aliases** when joining multiple tables
2. **Be specific with SELECT** - avoid `SELECT *` in production
3. **Use appropriate indexes** for WHERE and JOIN conditions
4. **Use LIMIT** when testing queries on large datasets
5. **Consistent naming conventions** for tables and columns
6. **Comment complex queries** for maintainability
7. **Use EXISTS instead of IN** for better performance with large subqueries
8. **Consider NULL handling** in WHERE conditions and JOINs
